Setup instructions

cp .env.example .env
docker compose up --build

Turtle config

Paste this shape into `/fleet/config.lua`, replacing `HOST` when Minecraft runs on another machine.

return {
  turtle_id = "fleet-dev-001",
  fleet_url = "ws://HOST:8787/turtle/ws",
  pairing_token = "dev-pairing-token",
  runtime_version = "0.1.0",
  dimension = "overworld",
  initial_facing = "north",
  initial_position = nil
}

What the stack gives you

The landing page is for setup. The console is where live operations happen.

Event-first control plane Every heartbeat, command, action result, world observation, lease, and failure is recorded for replay and diagnosis.
Lease-controlled actions Manual movement and queued work go through lease validation instead of blind remote-control spam.
Supervised turtle runtime Turtles keep local state, spool events, reconnect with backoff, and execute wrapped actions.
World model and diagnostics Known, unknown, stale, reserved, and failed states are visible to humans and MCP clients.
Factory-ready provisioning New turtles are created through an auditable factory workflow with bay leases and provider checks.
